# 内存范围、保护页与用户缓冲区契约

## 物理范围与地址对齐

E820 可用记录只发布完全位于区间内的页（起点向上、终点向下取整）；非可用记录排除任何被触及的页（起点向下、终点向上）。
重叠记录保留优先，与条目顺序无关。e820.h 统一范围转换与页可用性判断，metadata 和后续页发布使用同一规则。
长度在相加前截断到 4 GiB 上界；4 GiB 排他结束端点使用宽整数或 PFN 表示，不存入 32 位字节地址。

`page_ceil_checked(value, &result)` 返回 1 表示成功；无法表示对齐结果或输出指针为空时返回 0，不修改 result。
零长度可对齐为零；AnonMap 仍独立拒绝零长度。物理内存区域端点转换不使用这个 u32 字节接口。

## 物理页初始化顺序

page_init 解析 E820 并确定最高可用 PFN 上界。每个 PFN 使用 8 字节元数据，整个数组在 52–64 MiB 启动窗口内占一段连续可用页。
启动池发布时排除元数据和 E820 保留页，并按实际剩余页数核对正式分页所需的页目录、直接映射页表和 KMAP 页表预算。
正式页表建立后，page_publish_extended 在 direct_map_end 处分出低端和高端池，并发布其余可用页。
分页表构造辅助函数名为 init_identity_table；活动页目录查询沿用 paging_is_active，供分页和 uaccess 共用。

## 物理页水位与匿名回收

启动池和扩展池发布完成后，全局水位以实际发布的物理页总数为分母，低端和高端水位分别以本池发布页数为分母。物理地址空洞、保留页和分配器元数据不计入发布数。已经用于正式页表的启动池页计入发布数，当前不计入 `free_pages`。`nr_pages` 仍是最高可用 PFN 的上界。未发布页的池报告 `Normal`。每池的临界页数向上取整，低水位上界向下取整。

| 水位 | 空闲页比例 | 全局水位行为 |
| --- | --- | --- |
| `Normal` | `> 15%` | 按需分配照常进行 |
| `Low` | `5%–15%`，含两端 | 丢弃未锁定的可丢弃匿名页。回收评分至少为 400 的进程不能新增匿名预留，返回 `S_NOMEM` |
| `Critical` | `< 5%` | 延续 LOW 行为。没有可丢弃的驻留页时安排进程回收 |

`AnonMap` 按地址顺序遍历进程的 VMA，在匿名窗口中选择最低的足够大空洞。宽映像与尚未落页的匿名预留都占据虚拟地址空间。参数、配额和地址空间检查先于水位检查。VMA 节点分配失败返回 `S_LIMIT`，预留配额保持原值。已预留的匿名区仍可落页或解除映射。匿名数据页成功落地时增加 `pages_used`，VMA 节点计入内核 slab。

调度器每轮先尝试释放一个未锁定的可丢弃区。候选按进程回收分数、区内驻留页数从高到低排序，同分且同页数时先按进程槽顺序，再按区域虚拟地址从低到高。空区域不会被标为已丢弃。释放 PTE 和物理页的同时更新区内驻留数、`pages_used` 和 `free_pages`，保留虚拟预留与配额。已丢弃区后来按需落地的新页仍可以回收。锁计数归零或新增可丢弃驻留页会在压力水位下重新安排扫描。分数保护和缺页重试保护约束进程终止。显式标记的未锁定缓存页仍可丢弃。

`task::step()` 在内核页目录中处理到期事件和已有退出队列，再根据水位或匿名分配通知推进回收。每轮最多选择一个直接回收对象，跳过负分进程及有延后匿名缺页的进程。按回收评分、匿名驻留页数依次从大到小比较，再按槽号从小到大选取。

选定进程后，把它和同组的其他合格成员一同标为 `PROCESS_KILLED`，停止调度其线程。已退出、负分或等待匿名缺页重试的成员保持各自状态。直接选中的进程在本轮派发前释放，其余成员在下一轮由现有退出队列释放。每个进程释放后独立发布完成记录。重新读取水位后，空闲页恢复到至少 5% 或无合格进程时停止选择新的回收对象。

匿名补页在内核内区分数据页耗尽、低端内核页池无法分配页表，以及地址或权限冲突导致映射被拒绝。页表分配失败或映射被拒绝时，立即释放尚未交给页表的数据页。系统调用准备用户缓冲区失败时，两类内存不足返回 `S_NOMEM`，无效映射返回 `S_INVALID`。

全局临界水位下，Ring 3 首次访问遇到匿名数据页分配失败时，保留原指令帧，线程下次获调度时重新验证匿名区并补页一次。若另一线程已映射该页或补页成功，恢复原指令。地址失效或补页失败时，完成记录为 `PROCESS_FAULTED`、向量 14。页表分配失败单独记录并走常规缺页终止路径。调度器独立记录分池水位变化。丢弃区和进程回收日志包含每池释放前后的空闲数，主进程回收日志的差值覆盖当轮直接释放的主进程。

## Buddy 物理页分配

低端和高端池各维护 0–10 阶空闲块双向链表。每个块按自己的阶数对齐，释放时只与同池内同阶空闲伙伴合并。
E820 洞和元数据保留页切断可用区间。元数据位于直接映射内，高端页空闲链操作只访问元数据。
单页分配和释放最多检查各阶一次。内核页来自低端池，用户数据页优先从高端池分配，成功返回前都清零。高端取不到页时，用户数据页可在低端为 `Normal` 或 `Low` 时兜底。低端为 `Critical` 时拒绝兜底，页表、内核栈、slab 和内核堆保留各自的低端分配路径。该限制也适用于只有低端池的机器。

`kpage_alloc_run(count)` 返回恰好 1–128 个连续低端页。优先拆分 buddy 块并归还多余尾页。任何多页请求在快路径失败时，
都扫描低端池查找精确空闲区间，包括跨 buddy 对齐边界的区间。失败不改变页状态或空闲计数。
`kpage_free_run` 可释放原有内核页的大段或子段，只有整个范围均处于可释放状态才更新链表和计数。

## 内核 slab 缓存

`mm::slab_cache_create` 按对象大小取得共享缓存，支持 8、16、32、64、128、256、512、1024 字节八类。
`mm::slab_alloc` 返回按大小类对齐的未初始化对象，低端页不足时返回空指针。缓存以有空位和已满两条链管理整页，
页末的分配位图记录各 slot 的占用状态，空闲 slot 内保存下一个空闲索引。

`mm::slab_free` 通过页归属、slot 边界和位图验证指针，归属错误、内部地址或空闲 slot 均返回 false，状态保持原样。
最后一个对象释放时，整页立即归还 buddy。归属记录位于 PageFrame 的现有 8 字节布局内，普通页释放和 guard 入口拒绝 slab 页。
缓存操作运行在当前单核内核执行路径，硬件中断处理器不调用 slab。

## 内核通用堆

`kmalloc` 返回未初始化的内核内存。`kzalloc` 将请求的字节全部清零。零长度、超过 512 KiB 或分配失败时，两者均返回空指针。
1–1024 字节走可容纳请求的最小 slab 大小类，并按该类大小对齐。更大的请求从低端池分配连续页，并保证页对齐。
优先取得完整的对齐 buddy 块并保留尾页。多页请求只有在这条路径失败且空闲页总数足够时，才扫描低端池查找实际所需页数。
例如 8193 字节优先占 4 页，走精确兜底时占 3 页。堆分配的全部页标记为堆所有，头页记录实际分配页数供 `kfree` 使用。

`kfree(nullptr)` 直接返回。其他地址必须是仍在用的 slab slot 起点或大块基址，无效地址触发 panic。
普通页释放与 guard 入口拒绝堆页，堆释放也拒绝普通内核页。完整释放后，空 slab 页和大块页归还 buddy。

## 用户虚拟区间

每个进程用 AVL 树登记映像、参数页、用户栈及匿名区。节点使用半开页区间并记录权限，匿名节点另记驻留页数。PTE 记录实际映射。匿名分配即使被改权拆分或中途打洞，剩余片段仍共享分配 ID，并通过原始基址整份释放。洞内重新分配取得独立 ID。

每进程最多保留 128 份匿名分配、512 个匿名 VMA 片段（含分配头）和 128 MiB 匿名虚拟预留。实驻页数在首次触页时单独计数。整份释放完成后才归还分配 ID，局部解除映射归还相应字节配额并保留原分配身份。

范围改权和部分解除映射在修改树前验证整个范围、计算最终片段数并准备所需节点。改权保留驻留页，部分解除映射归还对应预留和实际驻留页。系统调用参数、配额及等待重试语义见 [os-interface.md](os-interface.md#anonymous-memory)。

## 用户态堆

`user/runtime.cpp` 为每个进程接入一份 `user/heap.h` 中的分配器，所有线程共享。1–4080 字节的请求按最小可容纳的大小类从 64 KiB slab 取槽。大小类为 16、32、64、128、256、496、1008、2032 和 4080 字节。块头后是活跃槽位图。分配先复用已释放的槽，再推进未使用槽的索引，映射时只初始化块头和位图。更大请求使用独立匿名映射，在 16 字节头部记录请求长度。两条路径都返回 16 字节对齐的地址。

| Slab 状态 | 分配与回收行为 |
| --- | --- |
| 活跃 | 同一大小类优先填充有空槽的活跃 slab；仍有存活对象的 slab 保持不可丢弃 |
| Hot | 空 slab 保留原大小类和空闲链；每类最多 1 个，全堆最多 4 个。同类替换或全局满额时降级到 cold |
| Cold | 全堆最多 12 个空 slab，超过预算先解除最旧映射。冷块标为可丢弃，内存压力下内核可回收驻留页。分配取最新冷块，先清除可丢弃标记，再按目标大小类重建 |

映射注册表、状态和缓存队列位于 slab 外，cold 丢弃覆盖块头时仍能查到映射。缓存最多保留 16 个匿名区域、合计 1 MiB 虚拟预留。内核丢弃只归还驻留页。大小块申请映射时，若注册表已满或 `AnonMap` 返回 `S_LIMIT`、`S_NOMEM`，先解除最旧的 cold 映射，cold 为空时选 hot。若重试仍失败，清空剩余空缓存后最后尝试一次，单次请求最多调用三次 `AnonMap`。

每进程一把堆锁，竞争时调用 `Yield(0)`。锁内完成注册表与缓存操作以及相关映射调用。`calloc` 清零和 `realloc` 复制在锁外执行，复制完成后再释放旧块。调用者负责同步同一对象的访问与生命周期。底层页按需驻留，进程退出时由内核统一回收活跃分配和空缓存。公开接口见 [os-interface.md](os-interface.md#anonymous-memory)。

## 内核保护页

`paging_kernel_guard(page, &owner)` / `paging_kernel_unguard(&owner)` 仅在正式页表建立后使用。
page 必须是调用方持有的、直接映射范围内的活动 kpage 分配；不能传用户后备页、保留页或已释放页。
调用方负责选择安全的页面，不能保护正在执行的栈、内核代码、页目录或页表等仍需访问的结构。
owner 是初始化为零的 KernelGuard，必须存放在被保护页之外，并在恢复前保持地址及生命周期稳定。

guard 保存完整原始 PTE，并清除映射；unguard 精确恢复原 PTE，分别执行 invlpg。共享内核 PDE 结构保持冻结。
记录绑定 owner 地址和不复用的序号；复制 owner 不转移权利。重复操作、错误 owner、越界或不对齐页面返回 S_INVALID；
16 个记录用完或序号耗尽返回 S_LIMIT；恢复时映射已被其他代码改变返回 S_CHANGED，不覆盖新映射。
失败不改变原状态。不得手动修改活动 owner；内核单核且这些操作不可抢占。

分配器区分用户物理页、普通内核页和受保护内核页。保护期间两类释放入口均拒绝回收该页；连续分配中有受保护页时整次释放失败。
恢复后才能释放或复用。进程内核栈用独立 owner 保存生命周期，分配失败清理和正常退出都按“恢复、释放”的顺序执行。
这不是一般页权限修改 API；只读页恢复后仍只读，不会升级为可写。

## 用户复制接口

- copy_from_user(pd, kernel_destination, user_address, bytes)
- copy_to_user(pd, user_address, kernel_source, bytes)
- copy_string_from_user(pd, kernel_destination, user_address, capacity)
- uaccess_prepare(pd, user_address, bytes, USER_READ / USER_WRITE)

所有接口要求 pd 属于当前进程且对应当前活动 CR3；不能用其他进程或非活动页目录校验后再解引用。
process_user_limit 检查当前所有者及虚拟范围，paging_is_active 检查硬件页目录。范围与权限校验不能相互代替。
内核侧缓冲区由调用方保证有效、容量充分且不与用户区混叠。READ 要求 PRESENT|USER，WRITE 还要求 WRITE；未知访问模式拒绝。

prepare 先验证整个范围，不因后半段非法而提前落地前半段；确认预留合法后再分配缺失匿名页。
若落页中途 OOM，已分配零页仍属于该进程，保留在原匿名区，计入页数；随后可访问、整区 unmap 或退出统一回收。
这类部分驻留不承诺回滚，但准备失败前不进行数据复制，也不能消费管道字节或修改文件。

固定长度复制完整 prepare 成功后才执行 memcpy，准备失败不更新目标缓冲区（允许上述匿名页驻留变化）。
字符串复制逐页检查，在 NUL 处立即结束；NUL 后下一页无需映射。字符串复制失败可留下已复制前缀；
调用方必须仅在返回 S_OK 后使用整个字符串，不承诺失败时 NUL 结尾。capacity 为零或用尽而无 NUL 返回 S_INVALID。
页面循环以最后一个页地址为终止条件，不依赖越过最后页后加法不溢出。

零字节范围不触页、不分配，但仍检查地址归属、边界、活动 CR3 和访问模式，不能用零长度绕过接口约束。

## 调用路径审计

| 路径 | 使用方式与顺序 |
| --- | --- |
| filesys.c 请求结构、文件路径 | copy_from_user / copy_string_from_user 到内核局部变量，成功后才执行对象操作 |
| SYS_SYSTEM_INFO / SYS_START_INFO | 构造内核局部结果，用 copy_to_user 完整校验后输出 |
| 文件范围读写、目录枚举、暂存提交 | 先 prepare 完整用户输出/输入范围；随后在当前系统调用内借用指针；有副作用的 finish 前已准备输出 |
| 管道和 CLI 流 | 先 prepare 后传输；保留已有部分传输语义；阻塞重试重新校验缓冲区 |
| terminal.c 会话、编辑、交互协议 | 所有读写缓冲区先 prepare；等待重试由 retry_wait 在切换到所属 pd 后重新校验 |
| 网络、旧式文件/进程查询、日志、控制台帧 | 先 prepare，使用期间保持所属地址空间活动，不保存裸指针跨调度使用 |

直接借用保留为有明确准备阶段的接口，不把所有流 I/O 改成额外拷贝。任何未来内核抢占、共享页 COW 或部分 unmap 机制都需重新审查指针有效期。

安装 RAM 与实际可管理页数不同，4 GiB 以上的重映射 RAM 在非 PAE 模式下不纳入物理池。

## 测试构建的分配失败注入

mm/test_fault.cpp 的后端仅在 SINO_SHELL_BRIDGE 构建中存在，不新增系统调用或普通用户控制入口。
启动路径核对 PROCESS_STRICT、只读 /boot 节点身份及精确参数后绑定目标页目录；可写副本不能启用。
映像模式在部分数据页分配后失败一次。页表模式让真实数据页分配成功后使新页表分配失败，检查数据页回滚、系统调用 `S_NOMEM` 和首次触页的隔离日志。
匿名模式允许首次零页落地，再拒绝该页目录后续匿名页分配，以验证跨页复制失败不消费管道数据、首次触页故障被隔离。
注入按页目录匹配，不限制其他进程或全局分配器；页目录销毁前清理记录，启动失败和正常/故障退出均走同一清理路径。
回收专项使用 ShellBridge 的测试阈值和只读 `reclaim.snx` 限定的匿名数据页注入，在实际页池计数和退出回收路径上验证水位决策。测试阈值覆盖由宿主命令撤销，或在关联探针的页目录销毁前撤销。普通镜像打包时排除 `reclaim.snx`，也不编译注入与阈值控制入口。

ShellBridge 的 `mem` 和 `free` 同时报告总空闲页数、各池空闲页数、发布页数和水位。`mmtest-watermark <crit> <normal>` 覆盖全局阈值，`mmtest-watermark <critLow> <normLow> <critHigh> <normHigh>` 独立覆盖分池阈值。所有阈值使用页数，`reset` 撤销两种覆盖。相关进程退出时只撤销其拥有的全局覆盖。
