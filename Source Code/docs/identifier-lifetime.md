# 编号生命周期与 PR-06 审计

适用于单核、内核不可抢占的当前实现。编号分配不在 IRQ 中执行，不增加堆分配或锁。
进程、对象、句柄、线程编号独立计数，不以清零或回绕解决耗尽。

## 编码与提交

| 标识 | 编码与作用域 | 耗尽处理 |
| --- | --- | --- |
| PID | `(generation << 4) \| (slot + 1)`；8 槽，各自 27 位代数；正 int | 每槽最多 134,217,727 次提交，末代退出后退役，所有槽不可用时 S_LIMIT |
| Object | 索引 + 每对象槽独立的完整 32 位 generation；Object 仍为 16 字节 | 每槽 4,294,967,295 代；销毁末代后跳过该槽，没有可用槽时 S_LIMIT |
| Handle | 保留 `(cookie << 8) \| (slot + 1)`；24 个低字节槽号，各有跨所有句柄表的 23 位计数器；Handle 仍为 16 字节 | 各槽最多 8,388,607 次；仅在本地空且未耗尽的槽中选择，全部不合格时 S_LIMIT |
| 新 TID | 保留 `(generation << 3) \| (slot + 1)`；全局 28 位代数 | 全局 268,435,455 次提交；分配栈/Object 前检查，耗尽返回 S_LIMIT |

零及负值不作为有效用户 token。PID 的数值不再承诺全局单调递增，调用者必须完整保存和传回，不能当作数组下标。
旧 SYS_THREAD 仍返回原始线程槽，保持旧 ABI；这里的 TID 预算指新线程创建接口。

PID 分配器的状态独立于会被清零的 Process。launch_policy 先预留槽，映像、页表、栈、启动句柄等失败时释放资源并撤销预留；不消耗代数。
全部准备完成后提交完整 PID、绑定完成记录、发布主线程。退出时摘队列、撤销等待与租约、关闭所有句柄、释放映像/页表/栈，再发布历史完成结果，清空 Process，最后允许编号槽复用。
alive/kill、终端取消和交互句柄查找都校验完整 PID。终端/租约/Shell 使用 u32 保存完整 PID；完成对象取消还同时匹配 completion_object。
旧完成记录保留旧 PID，其 cancel 不会重新绑定到同槽新进程。

提交是 launch_policy 的边界，不是所有外层接口都已经成功：交互启动随后还可能在目录或终端绑定时失败。
此时关闭已提交的进程与完成记录并回收执行槽，但已经提交的 PID、已创建的 Object、已签发的 cookie 仍计入消耗，不向后减代数。
这与提交前预留失败不同，避免内部已经使用过的标识再次签发。

## Object 与 Handle 的取舍

旧实现的 Object generation 和 cookie 都共用各自的全局 23 位计数器，频繁创建任意对象都会提前耗尽整个系统。
Object 的等待键、管道端点和 Handle 都同时保存索引与 u32 generation，因此本轮直接改成每槽 32 位代数，无需修改对象布局或用户 ABI。
不同对象槽出现相同 generation 没有歧义；销毁广播/清空旧等待桶，下次创建按新代数重绑，旧通知仍以索引和代数共同判定。

句柄低字节/正 int 编码保持，cookie 改成**按低字节槽号全局分配**，并在本地可用槽中选择消耗最少的一个。
cookie 不按进程或句柄表保存：相同原始 token 不会在另一进程的同槽重新签发，保留外来与陈旧句柄拒绝。
Dup 不新增 Object，但签发新 cookie；关闭和退出不归还已经使用的代数。检查参数失败不消耗，创建 Object 后因句柄不足而回滚仍消耗 Object 代数。

24 个槽合计最多 201,326,568 次句柄签发，是容量上界，**不是所有负载都能达到的保证**。
若某表长期占用 23 槽、只反复复用一个空槽，该槽仍可能在 8,388,607 次后耗尽；其他槽剩余预算不能突破该表的实际空槽约束。
存量末代句柄仍有效，只禁止从该槽签发下一代。

## 真实负载测量

证据：`Build Output/dev/runs/regression-20261114-033922-17bce165/pids-12baa172/shell-report.json` 的 identifierAudit。
宿主通过只读内存快照读取 56 字节 identifier_stats，不提供用户修改计数器的系统调用。
五个 u64 累计值依次是 PID 提交、PID 预留撤销、Object 创建、Handle 签发、新 TID 提交；随后四个 u32 是对应限制拒绝次数。
累计值反映分配/签发次数，不等于当前存活资源数。测量在工作负载结束且回收完成后取差值。

| 一次实际操作的范围 | PID | Object | cookie | TID |
| --- | ---: | ---: | ---: | ---: |
| 无完成对象的 spin 启动、kill、回收；重复 12 次，各次一致 | 1 | 0 | 0 | 0 |
| 已分配 8 个映像页后注入 OOM，撤销启动预留 | 0 | 0 | 0 | 0 |
| 父探针 + 两个 tracked 子进程，保留旧完成记录并取消新进程 | 3 | 2 | 2 | 0 |
| broker + 新 gsh 会话 + 一次严格 echo worker，随后关闭会话 | 3 | 6 | 13 | 0 |
| 文件探针 + 授权 /boot 目录 + 打开/read/关闭 readme.txt | 1 | 2 | 2 | 0 |
| 管道探针 + 一对端点 + write/read/关闭 | 1 | 2 | 2 | 0 |
| Event 探针 + 一次 create/dup/set/wait/关闭 + 填满 24 句柄 + 再创建失败 + 全关闭 | 1 | 26 | 26 | 0 |
| 线程探针 + 一个 joinable 的 create/join + 一个 detached 的 create/结束 | 1 | 1 | 0 | 2 |

表中父探针自身的 PID 明确计入。Shell 行包含冷建会话与 broker 的成本，不能直接当作常驻 Shell 每条命令的精确增量。
OOM 行另有 1 次预留撤销、没有 PID 提交；Event 行另有 1 次 handleLimits，失败的第 25 个 Event 消耗 1 次 Object 创建、0 次 cookie。
所有这些操作结束后，物理页、对象存活数和引用数均恢复各自操作前基线。历史完成、孤儿、取消、故障和交互绑定失败另由既有 completion / interactive / process 验证。

## 持续运行预算与后续触发条件

以下是空计数器起步、持续 **100 次签发/秒** 的算术预算，不是吞吐量测量：

| 计数器范围 | 到耗尽的时间 |
| --- | ---: |
| 一个热点 PID 槽 | 约 15.53 天 |
| 一个热点 Object 槽 | 约 497.10 天 |
| 句柄仅一个可复用槽 | 约 0.97 天 |
| 句柄 24 槽充分均衡的总预算 | 约 23.30 天 |
| 全局新 TID | 约 31.07 天 |

真实操作需乘以表中消耗率。例如每秒冷建 100 次上述 Shell 会话时，仅 cookie 总量上界约 1.79 天；每秒 1 次时约 179 天，受可用槽分布影响会更早。
两种新线程各创建一次消耗 2 个 TID，因此每秒 100 对的 TID 预算约 15.53 天；joinable 还消耗 1 个 Object，detached 没有结果 Object。
原全局 23 位 cookie 在每秒 1 个冷建 Shell 会话、每次 13 次签发时，只有约 7.47 天的算术预算。
扩大 Object 内部代数和均衡 cookie 已消除原全局计数器的早期瓶颈，但有限 token 空间不能承诺无限运行且绝无陈旧别名。

本轮不改 Handle 外部布局，也不扩大 TID ABI。需要长期高频创建服务、多用户常驻运行或容量突破 8×4 时，应先按真实每槽消耗和目标运行时长重新预算；
预测最早可用槽耗尽早于目标运行周期（建议至少留 2 倍余量）即触发下一轮设计，而不是允许回绕。
候选包括减少句柄槽编码位数并版本化 ABI，或更宽 token；必须同步系统调用、SDK、等待记录和权限测试，不能把 cookie 简单扩成 32 位后左移 8 位。

## 验证边界

test-identifiers 的 6 项直接编译生产编号算法，用缩小代数覆盖槽耗尽、预留撤销、不回绕、旧/畸形 token、正 int 最后值及 cookie 选槽。
ShellBridge 启动自检在任何用户程序启动前、对象引用全空时暂存元数据，调用真实 object_new/handle_open/duplicate/close 路径验证最后一代、S_LIMIT、引用不变、槽退役与陈旧拒绝，再恢复仅自检使用的状态。
正常镜像没有这段近耗尽注入，运行中没有重置用户编号的入口。
PID 专项 8 项负责实际进程复用、历史完成、OOM 回滚及上述负载审计；Event/线程专项验证对象复用后的等待/结果仍正确。
