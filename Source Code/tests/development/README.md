# 开发中临时测试

这里存放当前功能开发、迁移或缺陷定位需要的临时测试；稳定回归仍在 `tests/host/`、`tests/guest/` 和现有注册表中。此目录不被默认测试入口扫描或执行。

## 新建与执行

1. 使用 `<模块>/<功能>/`，例如 `mm/anonymous-memory/`；不以 Stage 编号、日期或构建编号组织长期入口。
2. 先在 [INDEX.md](INDEX.md) 登记，再为该功能添加自己的 `README.md`。没有当前条目时无需扫描本目录。
3. 功能 README 必须写明：所属模块与目标契约、何时启用、可复制的预览/执行命令、用例数、构建条件、产物路径、收尾条件。
4. 只运行当前功能条目；用例数计入同一步 50 项和单专项 20 项上限。AI 不通过临时测试绕过上限或补跑无关回归。
5. 复用现有通道、夹具和 VM 工具；客户机探针需要显式构建登记，不凭文件发现自动打包。临时测试不得调用其他业务套件来隐式准备状态，也不得自动加入 core 或稳定用例清单。
6. 私有 VM 和数据盘必须隔离。源码可随功能开发提交；编译产物、ISO、磁盘、日志和报告放在仓库根的 `Build Output/`，不放在本目录，不使用日常开发盘。
7. 用例 ID 按模块和行为命名，不含阶段编号或临时状态；迁入稳定回归时保留同一契约的 ID。

## 功能 README 最低内容

| 字段 | 必填内容 |
| --- | --- |
| 模块 / 功能 | 对应源码入口和本次正在建立的契约 |
| 启用条件 | 哪个功能开发或哪类缺陷调查需要执行 |
| 命令 | 从仓库根目录复制即可执行；标明构建目录参数、预览及实际执行 |
| 用例数 | 真实执行数，内部断言另列；新增、旧例和临时用例共同计数 |
| 构建 / 产物 | 普通或 ShellBridge 镜像、私有盘要求、Build Output 下的报告位置 |
| 收尾条件 | 达到哪个明确行为或接口契约后进行整理 |

## 完成开发时必须整理

- 有独有覆盖且验证长期契约：迁入对应稳定宿主/客户机套件，登记固定 ID 和功能入口，同步模块选测指南。
- 与稳定用例的行为、前置状态、环境和断言均相同：合并或删除，保留缺陷所需的独有边界。
- 主要用于反复恢复、资源耗尽或极端容量：迁入显式压力专项，默认不运行。
- 仅验证临时结构或开发过程：随临时机制删除；历史报告可以保留在 Build Output 中。
- 旧格式兼容仍属长期契约：按兼容行为命名后迁入稳定回归，不能仅因来自旧阶段而删除。

完成迁移或删除后，移除本功能目录及 INDEX 中的活动条目。只有该功能真正完成且必要覆盖已归属稳定套件时才清理，不以目录“临时”为由丢弃仍需维护的测试。
