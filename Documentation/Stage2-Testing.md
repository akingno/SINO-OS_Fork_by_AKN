# Stage 2 基础兼容测试

每完成一个 Stage 2 实施步骤，从仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\stage2-test.ps1
```

入口重新编译带 Shell 命令通道的普通内核镜像，不使用 SELFTEST 内核，不复用上轮通过结果。测试以命令输出、用户态自检、资源账目和持久化字节为依据；没有缩放、拖动、截图比对或鼠标坐标断言。无需关闭正在运行的日常开发 VM，测试不使用它的磁盘；同一源码目录的构建锁覆盖整个测试过程。

这里将“排除画图、文本文档”解释为排除画板和 GUI 文本编辑器的业务测试。文件系统的文本/二进制读写、Shell 重定向与保存仍属于底层基础能力，继续覆盖。

## 前置条件

使用现有 Node.js、支持 32 位目标的 GCC/Binutils、Python、仓库 NASM 和 QEMU。工具查找沿用原开发入口；必要时设置 SINO_TOOLCHAIN、SINO_PYTHON、SINO_QEMU_DIR。本集不需要 Pillow 或额外测试框架。

普通/测试镜像与原有 22 组 GUI/系统回归仍有自己的使用规则，见 [testing.md](../Source%20Code/docs/testing.md)。本入口独立运行，不能把它的通过结果记为完整 22 组门禁通过。

## 覆盖范围

| 分组 | 检查内容 |
| --- | --- |
| infrastructure | 复用 43 项实际 storage/klog/locale 宿主契约，包括提交失败、恢复边界、字节日志和资源生成校验 |
| rtc-driver | 编译实际 RTC 驱动与可控寄存器后端，覆盖采样、BCD/12 小时制、缓存与回绕 |
| shell-transport | 复用 25 项命令通道检查，包括 UTF-8、分段帧、错误、输出超限和后续请求恢复 |
| shell-commands | 复用 112 项现有 Shell 命令与语法断言，状态和输出分别检查 |
| native-contracts | 真正 Ring 3 的权限、指针、线程、句柄降权/过期/限额、64 KiB 二进制文件、重复退出回收、故障隔离、抢占、进程表满额、定向终止；计算器、时钟、Files、BASIC、安装服务自检及回环网络 |
| cold-reboot | 将本轮私有盘复制后冷启动，核对二进制内容、Shell 文件和安装事务恢复；原测试盘不被下一阶段修改 |
| runner-rejects-failure | 在另一台私有 VM 中故意触发用户测试失败，确认子报告 FAIL、返回非零且 VM 已关闭；只接受指定的预期失败原因 |

Files 与网络自检仍可能在无显示 VM 内创建临时窗口，目的是运行现有应用代码和检查对象回收；不检查布局或像素，不模拟复杂 GUI 操作。画板、GUI 文本编辑器、可视化设计器交互、图形模式切换、真实系统安装及外部网络均不在本集范围。

原有测试文件没有被删除。本基础集适合每步开发后的常规门禁；如果一项修改实际影响窗口渲染、输入、安装引导等未覆盖区域，应单独运行对应已有专项，不能据此保证整个桌面无回归。

## 运行与失败的含义

宿主退出码 0 表示所有分组通过；1 表示构建、身份校验、断言、超时或清理存在失败。构建失败不会拿旧镜像继续测试。分组失败后后续分组保留 NOT-RUN，不把未执行记为通过。

报告位于本轮打印的目录：

```text
Build Output/dev/runs/stage2-<时间>-<编号>/
  stage2-report.json       总报告、源码/镜像身份、分组结果
  SINO.iso                本轮独立 ISO
  kernel-normal.exe       与该内核匹配的符号快照
  infrastructure/         实际 C 代码宿主测试报告
  rtc-output.txt          RTC 驱动文本结果
  transport/              命令通道结果、每条原始输出及私有盘
  commands/               Shell 行为结果及私有盘
  native/                 用户态结果、资源账目、内核日志及私有盘
  reboot/                 冷启动副本、恢复结果及日志
  intentional-failure/    故意失败的原始证据
```

总报告中的 runner-rejects-failure 应为 PASS，其子报告应为 FAIL；这是对失败检测能力的检查，不是忽略实际回归。任何其他失败原因、启动失败或 VM 未清理，都不能让这一分组通过。

所有 VM 的 QMP/串口只监听回环地址，显示关闭，外部网卡关闭。挂载只允许该子目录 ISO 和私有盘。源码与 ISO 在运行前后核对，符号快照先还原为平面内核并校验；不猜测“最近一次构建”。不读取或写入日常开发盘、发行盘或物理磁盘。

## 它证明什么，以及还不能证明什么

该集验证现有能力的行为基线，尚不代表 Stage 2 的 SpawnEx、可靠 wait、标准流、文件对象或细粒度权限已经实现。新接口每落地一项，都应将它的正反例加入本集，并更新完成标准。

目前 Shell run 只返回启动结果。原生自检会等待本轮新日志、确认对应 PID 已回收、检查正常退出/故障计数与资源；不把启动成功当成程序测试成功。但这仍不是未来可保留、可直接读取最终退出码的 wait 契约，必须继续建设完成对象。

大部分测试运行本轮重编译的程序，不能单独证明任意历史 SNX 的二进制兼容性。修改 ABI 编号、布局或旧接口语义前，应加入相应旧二进制固定夹具，并以原封不动的旧程序验收；不能靠同时重编内核与应用掩盖不兼容变更。

固定表和结构布局的私有检查适配器如果失效，会明确失败并要求检查，不自动猜新偏移。限额测试中的 8 个进程、24 个句柄、64 KiB 文件是当前基线；有意改变限制时，应一并审查契约与测试。不能为通过测试而随意降低检查要求。

## 底层与接口层如何分步开发

不建议建立第二套内核或复制一套文件系统。保留原应用和旧 ABI，新接口在其旁边增加，由薄适配层调用同一套受测核心实现；旧接口保持原返回值和权限行为，严格权限模式由可信启动者按进程设置。

内存与 VFS 不必“全部完善”才建设接口。先确保已有分配/释放、边界、失败回滚与资源回收可信；每个接口只补它当下需要的能力。例如完成对象先建立有界记录，不要求先有通用用户堆；标准流先使用有限捕获，不要求先有完整文件流或 TTY。

接口边界可以减少相互影响，不能消除共享实现的影响。更换页分配器、VFS 或提交路径仍可能影响所有调用者，所以每一步运行本集。旧软件要等替代功能与数据兼容得到验证后再迁移或退役，不以先删除旧软件来回避兼容问题。
